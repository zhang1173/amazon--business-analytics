# 同事资金沙盘手册评估

2026-10-29 · 11

## 结论

手册是一套严谨、可复算的"单产品资金沙盘"，教学案例逐项重算，全部数字都对，没有发现算术错误。它比我们定稿方案精细的地方主要在**回款日期、退款、仓储、Coupon 费、库存成本**五项，建议直接采用它的口径。

但它刻意不做我们最关心的三层：**起点现金和团队开支、关税、推广力度与销量的关系**。它从 0 元起算、明说公司资金不要填进去、税费不在范围内、广告只是固定输入不反推销量。所以它回答不了"每月能给团队多少"和"工厂到期那天够不够"。

**建议合并方式**：它的引擎做产品层（卖多少、什么时候到账、经营贡献），我们在上面加资金层（起点现金、团队开支、关税、工厂到期日逐日余额）和推广杠杆层（CPC÷CVR 推广告费、每单广告上限、coupon 档对比）。两个真正要定的冲突：缺货是递延还是丢单（它递延，我们应按丢单）；资金看月末还是看逐日（它只看月末，我们必须逐日）。

手册背后有一套已有的 Python 程序（D08-FLEX 1.2，79 项自动测试通过），存放在同事电脑上。如果同事愿意给代码和"旧拉链款"方案数据，app 的计算核心不必从零写。

## 它的沙盘逻辑和算法

核心思路：同一笔销售分开记三本账，日期各不相同。**库存账**答货到了没、卖了多少；**经营贡献账**答这批履约赚了多少；**现金账**答钱哪天进、哪天出。所有收付都化成带日期的"现金事件"，按现金日按月汇总。

计算顺序（每天一轮）：月计划拆到每天 → 当天先到货再履约，只有库存支持的销量才算收入 → 缺货的需求排队递延 → 每周一按覆盖天数自动补货 → 按成交价组算佣金、FBA、退款、Coupon 费 → FIFO 成本层算销售成本 → 按释放分布和 14 天打款日历排回款 → 月净现金、累计现金、峰值缺口、稳定回正月。

| 模块 | 它的算法 |
| --- | --- |
| 销量展开 | 月销量按自然日均分成整数，全月合计严格等于月计划；也可逐日填 |
| 履约 | 预测可履约量 = MIN(待履约需求, 可售库存)；缺的部分保留到以后有货再卖，按履约日的售价和券 |
| 补货 | 每周一投影未来库存；缺口 = 到货日次日起覆盖天数内的需求 + 积压 − 预计库存；支持全空、全海、空海结合 |
| 佣金 | 按每个成交价组分档 5% / 10% / 17%，最低 $0.30，不能用均价选档 |
| 退款 | 每件净影响 = 成交价 − 原佣金 + MIN($5, 佣金×20%) + 退货物流费；FBA 费不退；可售退回按原成本回库 |
| 仓储 | 日末可售库存 × 单件月费 ÷ 当月天数，按月计提，次月打款日扣 |
| Coupon 费 | 每活动固定 $5 + 用券后销售额 × 2.5%，单活动上限 $2,000，跨月共用上限 |
| 广告 | 计划金额当天出账，与销量无关，缺货也照扣 |
| 成本 | FIFO 成本层（采购 + 头程），卖出才进经营贡献；采购款整批进现金 |
| 货款 | 采购付款日 = 发货日 + 账期日历月数；头程 = 发货日 + 天数；每批一次全额 |
| 回款 | 当日净额（收入 − 佣金 − FBA）按"滞后天数 × 权重"分桶释放，再顺延到下一个 14 天打款日 |
| 资金指标 | 累计现金从 0 起；峰值缺口 = 月末累计现金最低点；稳定回正月 = 从该月起到尾期每月都 ≥ 0 |
| 压力情景 | 回款释放再延迟 N 天，金额不变，重算缺口 |
| 止损 | 指定月月末清库，按 FIFO 成本 × 净回收率变现 |

它还有四项守恒检查（数量、成本、现金、活动上限），任一失败就不出结果；以及"输入事实 / 运营假设 / 模型推演"三类结论分开写的交接规矩。币种：平台收费用 USD，采购、头程、资金结果用 CNY，一条固定汇率。

## 与我们定稿方案的对照

两边的骨架一致：都是"一件货的账 → 每天的账 → 按月汇总 → 库存与补货 → 现金流"，都强调按下单月和按到账月是两个口径。下表列具体差异。

| 项目 | 我们定稿 | 同事手册 | 判断 |
| --- | --- | --- | --- |
| 佣金分档 | 5% / 10% / 17%，按用券不用券分别算 | 同，按价格组分别选档 | 一致 |
| 头程成本 | 空运 / 快船单件，按计费重 | 空运 / 海运单件 CNY，进 FIFO 成本层 | 一致 |
| 补货周期 | 做货 5 周 + 美森 4 周 | 生产天数 + 至可售天数，每周一自动算 | 一致，它的自动化 |
| 两个月份口径 | 下单月 vs 回款月 | 发生来源日 vs 现金日 | 一致 |
| 货款付款 | 按工厂账期到期日付 | 发货日 + 账期月数，或手填未付日期 | 一致；它不支持按卖出结算、订金尾款 |
| 回款日期 | 下单 + 25 天，100% 到账 | 释放分布 + 14 天打款日历 | 它更准，采用它的 |
| 退货损失 | 成交价 × 8% | 退款净影响 + 物流费 − 可售回库成本 | 它更准，采用它的 |
| 仓储费 | 每卖一件 $0.09 | 日末库存 × 月费，按月覆盖淡旺季 | 它更准，我们审核时已标记要改 |
| Coupon 费 | 券后价 × 用券单 × 2.5% | 另加 $5 固定费和 $2,000 上限 | 它更全，补进来 |
| 广告出账时间 | 按实际扣款方式（余额扣 / 信用卡） | 计划当天出账 | 小冲突；它更保守，可先用 |
| 缺货 | 断货 = 卖不了，必须提前下单 | 需求递延，有货再卖，不丢单 | **冲突**，新品推广期应按丢单 |
| 资金最低点 | 每天余额，工厂到期日够不够 | 只算月末累计现金最低点 | **冲突**，必须逐日 |
| 起点现金、团队开支 | 核心输入，算每月可拨团队 | 从 0 起算，明说不填公司资金 | 我们有它没有 |
| 关税 | 最优先确认项 | 税费不在范围 | 我们有它没有 |
| 推广杠杆 | CPC ÷ CVR × 广告单 = 广告费；TACOS；每单广告上限 | 广告是固定预算，不反推销量 | 我们有它没有 |
| coupon 档 × 推广节奏对比 | 每件剩多少、广告占比上限 | 方案比较只比结果，不给上限 | 我们有它没有 |
| 向工厂滚动借款条件 | 月销量 × 每件剩 ≥ 月开支 | 无 | 我们有它没有 |
| prime 折扣叠加 | 有（隐藏列） | 只有 coupon | 我们有它没有，次要 |
| FIFO 成本层、期初在途 / 已付未付 | 无，首批 4,000 件未接入库存 | 有，含期初剩余量校验 | 它有我们没有，吸收 |
| 月末待收 / 已发未付 / 库存货值 | 无 | 有 | 它有我们没有，吸收 |
| 慢回款压力情景 | 无 | 有 | 它有我们没有，吸收 |
| 止损清库 | 止损线只到 TACOS / 单量 | 指定月清库变现 | 它有我们没有，吸收 |
| 稳定回正月、守恒检查、三类结论分开 | 无 | 有 | 它有我们没有，吸收 |
| 赠品、日 / 月计划模式 | 无 | 有 | 它有，我们暂不需要 |
| 币种 | 主要用 USD，汇率 6.7 / 6.8 混用 | 平台 USD、资金 CNY，一条汇率 | 采用它的 |

我们的"回款流覆盖未来 3 个月"判断，它用"稳定回正月 + 峰值缺口 + 已发未付"代替，更清楚，建议换成它的。

## 算错或假设问题

教学案例（第 6 章）我用手册的公式逐项重算：收入、佣金、退款净影响、三个月仓储、每笔回款日期和金额、月净现金、压力情景、贡献与现金的勾稽，全部对得上，没有算术错误。佣金三档、退款管理费 MIN($5, 佣金×20%)、FBA 费不退，也符合亚马逊美国站服装类规则。问题都在假设和范围，按对我们结论的影响排序：

1. **缺货递延不丢单**。它把缺货期的需求排队，到货后照卖。新品推广期断货实际是丢单加掉排名，这样算会高估回款。我们应按丢单，或做成开关。
2. **只看月末资金最低点**。它自己的案例就说明了问题：月末缺口 0，但月内最多垫 1,635 元。工厂到期日不一定在月末，我们必须按日算。它第 5.9 节给了做法，但程序没做。
3. **广告不影响销量，销量不影响广告**。这是它的设计立场，不是错。但我们要把推广力度当杠杆调，就必须在它外面加 CPC ÷ CVR × 广告单这层，把算出的广告费和销量喂给它。
4. **累计现金从 0 起，不含公司资金和团队开支**。它的"稳定回正月"和"峰值缺口"都是产品层的数，不是账上余额。我们前 11 天已花的 $18,015 广告要填进它的"期前累计净投入 H"。
5. **没有关税**。它明说税费不在范围，左右我们结论的关税问题它解决不了。
6. **释放分布来自旧样本**。模板里 34 个桶来自旧 D08 的 TM 店铺历史，样本起点是下单日，程序却从履约日起算，还可能漏长尾。它自己标注了，用前要用本店结算报告校。
7. **退款率等于退货率**。只退款不退货、退回不可售的报废都没分开。我们 8% × 成交价的粗算比它保守，对内衣这种退回难再售的品类，可售退回比例要填低。
8. **广告按计划当天出账**。如果实际从亚马逊余额扣，现金影响在下一个打款日；它的算法偏保守，影响小。
9. **货款每批一次全额，账期从发货日起**。我们要确认工厂账期是从发货日、交货日还是按卖出结算；后两种它不支持，要手填付款日或另算。
10. **补货不考虑起订量、整箱、工厂产能**；覆盖天数从到货次日起算（T+1），自己建表核对时会差一天。
11. **止损清库按固定比例即时变现**，不考虑处置周期。用作参考即可。

## 合并建议

分三层：它的引擎做产品层，我们在上面加推广杠杆层和资金层。我们定稿的《指标与联动说明》的结论和框架不变，只换五个计算口径。

| 层 | 负责回答 | 用谁的 |
| --- | --- | --- |
| 推广杠杆层 | 这个 coupon 档、这个推广节奏下，每天卖多少、广告花多少；每单广告上限和止损线 | 我们的（CPC ÷ CVR × 广告单、TACOS、coupon 档对比表） |
| 产品层 | 库存撑不撑得住、什么时候补货、钱哪天到账、经营贡献多少 | 它的（事件表、FIFO、释放分布 + 14 天打款、退款、仓储、Coupon 费、守恒检查） |
| 资金层 | 账上余额会不会穿底、工厂到期那天够不够、每月能给团队多少、滚动借款会不会越滚越大 | 我们的（起点现金 + 团队开支付款日 + 关税 + 它的现金事件表按日累计） |

**直接换成它的口径**（写进我们的方案）：

- 回款：用释放分布 + 14 天打款日历，代替"下单 + 25 天"。这正好回答了我们第七节的回款周期问题。
- 退货：按退款净影响 + 退货物流费，可售退回按成本回库，代替 8% × 成交价。
- 仓储：按日末库存 × 月费，10 到 12 月用旺季费率。
- Coupon 费：加 $5 固定费和单活动 $2,000 上限。
- 库存和成本：用它的期初库存 / 在途 / 已付未付录入规则，首批 4,000 件作为期初批次。
- 指标：用"稳定回正月 + 峰值缺口 + 已发未付"代替"覆盖未来 3 个月"。
- 币种：平台层 USD，资金层 CNY，一条汇率。

**必须加在它之上的**：起点现金、团队月开支和付款日、关税、工厂到期日逐日余额、每月可拨团队金额、推广杠杆模型、缺货按丢单、按卖出结算或分期付款的货款。

**要向同事要的东西**：

1. D08-FLEX 1.2 的完整程序（engine.py、planning.py、goods.py）和教学案例的输入文件，用来验证能不能当我们的计算核心。
2. "旧拉链款"已保存方案。手册提到它有广告预算、库存批次、历史投入，很可能就是前拉链三件套的真实数据。
3. TM 店铺的 34 桶释放分布和打款锚点日，再用本店结算报告校对。
4. 佣金、Coupon 费、退款管理费的官方费率页截图或链接。

**对 app 计划的影响**：如果能拿到代码，建议 app 的计算核心直接用它的引擎，我们只写推广杠杆层、资金层和界面，工作量少一半以上，而且有 79 项测试兜底。拿不到代码，就按它的现金事件表设计自己写，用它的教学案例（第 6 章，数字已复核）当我们的验收用例。两条路都要先把上面两个冲突（缺货丢单、逐日资金）定下来。
