# 推广 × 现金流 平衡工具（第一版，2026-11-01）

回答一个问题：**在给定现金和工厂账期下，推广花多少、花多久、什么时候回款、现金什么时候最紧、工厂到期付不付得清、团队能不能被供养。**

计算分三层（详见 `../app架构设计.md`）：

| 层 | 谁写的 | 做什么 |
| --- | --- | --- |
| 推广杠杆层 `promo_layer.py` | 我们 | 推广阶段（售价、coupon、CPC、转化率、广告单占比、单量或预算）→ 逐日单量、广告、Coupon 活动；每件的账和止损线 |
| 产品层 `engine_d08/`（D08 v1.7） | 同事 | 逐日库存 FIFO、销售结算（佣金、FBA、退款、仓储、coupon 费）、释放分布 + 14 天打款、自动补货、货款头程按账期出账、缺货丢单 |
| 资金层 `cash_layer.py` | 我们 | 起点现金、团队开支与付款日、一次性费用、关税、广告出账方式、断货停广告、逐日余额、工厂到期日余额、每月可拨、反推、方案对比矩阵 |

## 运行

需要 Python 3.9+，不需要安装任何第三方库（生成 Excel 模板时才需要 openpyxl）。

```bash
cd 项目交接/推广现金流工具
python3 run.py inputs/Y背默认.json --matrix        # 跑默认方案 + coupon×节奏 对比
python3 run.py inputs/输入表_Y背默认.xlsx --matrix  # 直接读 Excel 输入表
python3 -m unittest tests.test_tool                 # 自检（15 项）
```

结果写在 `输出/<方案名>/`：`报告.html`（一页看完）、`月度.csv`、`逐日资金.csv`、`现金事件.csv`、`工厂到期.csv`、`回款周表.csv`、`补货批次.csv`、`推广阶段每件账.csv`、`方案对比.csv`、`结果摘要.json`、`引擎输入.json`（喂给同事引擎的原始参数，便于核对）。

**引擎在哪里找：** 依次找环境变量 `ENGINE_DIR`、本目录 `engine_d08/`、`../../参考资料/财务交接包_20261030_摘取/程序快照/`。同事程序不进公开仓库，所以 `engine_d08/` 在 `.gitignore` 里；本机运行时把程序快照的 5 个文件（engine.py、planning.py、goods.py、goal_finance.py、operations.py）放到任一位置即可。

## 输入表怎么填

两种输入等价：`inputs/*.json`（程序用）和 `inputs/输入表_*.xlsx`（人填）。Excel 有 9 个页签：

1. **参数**：只改"值"列。黄色行待确认，红色行最优先确认（关税）。
2. **推广阶段**：一行一个阶段，日期不重叠。
   - 填法 `orders`：填每天单量（或阶段总单量 + 形状），广告 = 单量 × 广告单占比 × CPC ÷ 转化率
   - 填法 `ads`：填每天广告预算，广告单 = 预算 ÷ (CPC ÷ 转化率)，总单量 = 广告单 ÷ 广告单占比
   - 填法 `both`：单量和广告都直接填（同事方案就是这种）
   - "起"和"止"两列都填 = 阶段内线性变化（例：CPC 7 → 3.4）
3. **发货批次**：已发/已到的货，含起点剩余量和货款、头程的付款方式（terms 按账期 / paid 已付 / unpaid 未付填预计付款日）。
4. **计划补货批次**：已经决定要下的单。没填就由引擎按"覆盖天数 + 安全天数"每周一自动建议海运补货，补货的货款头程按账期算进现金。
5. **团队开支**：每月固定开支和付款日。6. **一次性费用**。7. **回款分布**（默认 TM 店铺 68,057 单）。8. **待确认**：参数清单，填完改状态。

## 报告怎么读

- **六个问题的答案**：每张卡一个结论和红绿判定。先看"工厂到期付得清吗"和"团队能被供养吗"。
- **账上余额曲线**：含团队开支；虚线是工厂货款/头程到期日；红色阴影是断货。最低点就是前期最多要垫的钱。
- **每件的账与止损线**：每件广告上限 = 扣广告前每件剩的钱（团队一分不拿时）；"按 CPC÷CVR×占比"是推广假设算出来的每件广告，超上限就是卖一件亏一件。
- **反推**：到每笔货款到期日前至少要卖多少件（粗算，不计回款滞后）。
- **方案对比**：coupon 档 × 推广节奏，先挑"工厂到期都够、期末余额为正"的格子。
- **可额外拨**：在已付团队固定开支之外，每月月末还能拿出而不让以后任何一天余额低于底线的钱。它是 0 不代表团队没钱发（固定开支已经扣了），而是说没有多余的。

## 口径（和定稿一致的地方、不一致的地方）

- 现金按人民币，平台指标按美元，一条汇率。
- 货款、头程按工厂账期**到期日**出账（不是发货当月）。第二批默认同样账期，待确认。
- 回款：销售净结算款（已扣佣金、FBA）按历史释放分布落到释放日，再按 14 天打款日历到账；退款、退货处理费、仓储、coupon 费同样走打款日历。
- 广告出账三选一：花费当天 / 下个打款日从余额扣 / 信用卡还款日。
- 缺货按丢单（不递延），断货当天的广告默认停掉。
- 退款按同事引擎公式：退货率 × (成交价 − 佣金 + MIN($5, 佣金×20%)) + 退货物流费；可再售部分按成本回库。
- 仓储按日末库存 × 月费（可分淡旺季）。Coupon：每活动 $5 固定 + 2.5% 变动、封顶 $2,000，活动 ≤30 天自动切段。
- 关税：每件美元或按采购价比例，到仓时付。默认 0（包税），**最优先确认**。
- 工厂付款只支持整批三种：按账期到期日付（terms，默认）、已付（paid）、不付（unpaid）；**不支持**按卖出结算、分期、定金尾款。
- 每件账的 FBA 和仓储按阶段日期落在旺季窗口的天数（按单量加权）取旺季价，和引擎同口径。
- 每件广告上限给两个数：计可再售回库（退货率 × 可再售率 × 货值回库）和不计回库；拿不准时按不计回库的保守值。
- 首笔回款 = 平台单日净到账 ≥ ¥100 的第一天（释放分布第 0 天桶会产生几分钱，忽略）。
- “现金最紧”分两段看：推广期低点（最后一个推广日之前的最低余额）和期末余额（止月截断，期末库存按货值 + 关税算未变现）。
- 工厂到期“最多要垫”= 各到期日缺口的最大值（同一笔负余额不重复相加）。
- 经营贡献 = 引擎贡献（销售 − 平台费 − 广告 − 仓储 − 货值头程）− 卖出件的关税 − 当月一次性费用。
- 没算的：入库配置费、库龄附加费、Vine 等上新费用（可填一次性费用）、店铺其他产品共用余额、预留金。

## 网页版（自己填数、马上出方案）

- 在线：https://claude.ai/artifact/ThBASVeKg4kgniRuHU2t1d 。按 app 做：**总览**（走得通 / 走不通、三个杠杆：推广节奏 / coupon / 关税、六个数、余额和库存曲线、六个问题）、**填数字**（分 5 步：钱和团队 → 货和账期 → 补货 → 推广计划 → 平台费，推广阶段是卡片）、**方案对比**（节奏 × coupon 表，推荐行高亮；关税敏感性）、**明细**（按月、到期付款、每件账与反推、回款周表、补货批次、口径）、**设置**（换预设、复制摘要、导出 / 导入 JSON）。手机底部导航，电脑左侧栏，深色模式自动。参数只存在浏览器本地。
- 源码在 `app/`：`model.js` 是整套模型的 JavaScript 版（推广层 + 引擎子集 + 资金层 + 推荐搜索，口径与 Python 完全一致，`compare.js` 用三套输入逐项对照过）；`ui.js` 是界面；`page.html` 是模板；`build.py` 把三者和 `inputs/` 里的预设拼成单文件网页。
- 本地打开：`app/沙盘网页（可直接打开）.html` 双击即可（和在线版同一份代码）。
- 改了 Python 口径后，同步改 `model.js`，跑 `node app/compare.js ref_*.json` 对照（参考输出用 `python3 app/dump_ref.py Y背真数_20261101 Y背默认 原表格推广假设` 从 Python 侧导出），再 `cd app && python3 build.py` 重新拼装；界面自测 `node app/test_page.js`（需要 Playwright，会在电脑 / 手机 / 深色三种视口下跑一遍并截图）。
- 推荐方案的规则：在 coupon 档 × 节奏档（把每天单量和广告同比例缩放）的网格里，找"工厂每笔到期都够付 + 全程不低于底线"的组合，按"期末余额 + 期末库存货值"取最好；都不可行时取最少要垫的组合，并对你填的方案二分搜索"起点现金要多多少 / 关税最高多少 / 团队月开支最高多少"。
