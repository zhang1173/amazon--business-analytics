## 二、财务包口径与单价回款 $9.31（重点 2）

**$9.31 按方案稿的公式算是对的；但这个公式比财务包自己的退款算法保守 $0.31/件，要用户定。**

工具的财务包预设：FBA $6.50、退货率 10%、退货处理费 $3、仓储 $0.11、coupon 费 2.5%，货值头程按发货批次 FIFO（首批 55.5 + 5 元 ÷ 6.8 = $8.16 + $0.74 = $8.90）。按 $29.99、30% 券、80% 用券复算：

| 项 | 算法 | 金额 $ |
|---|---|---|
| 成交均价 | 29.99 × (1 − 0.3 × 0.8) | 22.7924 |
| 佣金 | 四档加权（同 Excel） | 3.876 |
| FBA | 财务包 | 6.50 |
| 退货损失 | 22.7924 × 10% + 10% × 3 | 2.5792 |
| coupon 费 | 20.993 × 0.8 × 2.5% | 0.4199 |
| 仓储 | 财务包 | 0.11 |
| **单价回款** | 均价 − 以上各项 | **9.3073 → $9.31** |
| 每件毛利（不计广告） | 9.31 − 8.90 | 0.41 |

原表格口径（$6.04 / 8% / $0.09）算得 $10.5431，与 Excel L4 一致。

**口径问题（速览第 2 条）：** 退货损失按"退货率 × 成交均价 + 退货率 × $3"，等于说退一单连佣金都损掉。亚马逊退款时会退还佣金，只扣退款管理费 min($5, 佣金 × 20%)，FBA 费不退；财务包的 D08 引擎每笔退款就是这样算的（成交价 − 佣金 + MIN($5, 佣金 × 20%) + $3）。按它：每笔退款损 22.7924 − 3.876 + 0.775 + 3 = 22.69，× 10% = 2.269，比工具少 $0.31，单价回款 ≈ **$9.62**，2,600 套约 +$800。方案稿写的是简式且用户已核对通过，所以这条不是"算错"，是要用户选：改成财务包公式，或保留简式并在参数页注明"退款损失含佣金，偏保守"。

两点只说明、不改：财务包说 90% 退货可再售回库，工具按退货件的货值全部损失（和原表格一样，偏保守；前几轮审核都认为内衣退货多半不能再卖）；coupon 费亚马逊是每个 coupon $5 + 券销售额 2.5%，工具和原表格一样只算 2.5%，差额很小。FBA $6.50 和仓储 $0.11 财务包自己标"待核"，参数页能改。

## 三、资金盘规则：DD+7、14/28 号结算、信用卡、账期到期（重点 3）

**规则和方案稿第八节写的一致，我用原表格 11 天逐笔手算，每一笔的日期和金额都对。**

ledger() 的实现：送达 = 下单 + 2 天；释放 = 送达 + 7 天；结算日默认每月 14 / 28 号（可改成"从某日起每 14 天"：锤点 2026-11-02 → 11/02、11/16、11/30、12/14、12/28…1/11，复算一致）；某结算日打的款 = 释放日落在（上次结算日, 本次结算日] 的订单回款，即送达日在"上次结算 − 7 到本次结算 − 7"之间，和稿里的说法一致；同期（按下单日）的广告从打款里扣：回款 ≥ 广告 → 两项都在结算日 + 5 天入账；回款 < 广告 → 两项都记在结算日当天，差额就是信用卡付的广告；口径 B 按需提现 = 释放 + 5 天到账、广告当天付；固定开支每月 15 号 ¥70,000；货款 = 发货日 + 6 个月（首批 2027-03-30 ¥144,300），头程 = 发货日 + 60 天（2026-11-29 ¥13,000）。

方案稿的例子（11/7 的单：11/9 送达、11/16 释放、11/28 结算、约 12/3 到账；按需提现约 11/21）工具算得一样，测试覆盖。

两点说明：(a) 回款不够扣广告时，整笔回款和广告都记在结算日当天，等于差额当天刷卡，是合理简化；(b) 广告按"下单日落在哪个结算期"扣，亚马逊实际是广告账单到额度或月结时扣，日期有几天出入，不影响月度。

小问题（速览第 4 条）：按需提现口径下，广告事件记在下单当天，起点日（2026-11-01）之前的日期行会被"只算起点之后的事件"过滤掉；自动结算口径把广告挂在结算日，不受影响。建议起点前的广告归到起点日，或提示"起点日前的行不进资金盘"。

## 四、纯现金流、覆盖未来三个月、全年表是否同口径（重点 4）

**月份统计、纯现金流、全年表的每一项都能在 Excel 里找到对应公式；唯一的口径差在"覆盖未来三个月"的"数据不足"判断（应改）。**

**月份统计-运营视角（Excel 汇总表 G–T 列）**：单量 = SUMIFS 按下单月；日均 = 单量 ÷ 当月行数（COUNTIF，含 0 单的行）；货值 = 每件货值 × 单量；头程 = 混发加权单价 × 单量；广告、占比、销售额、利润、毛利率、增幅 = 本月单量 ÷ 上月单量 − 1；"预估该月周期回款"和"结算毛利"是按**回款日期（下单 + 25）落的月**汇的，不是整体平移一个月。工具 monthly 的 units / dailyAvg / goods / freight / ad / tacos / netByOrder / netByPay / profit / profitByPay / margin / sales / growth 逐一对应，合计行同；折人民币按参数汇率 6.8（Excel M17 注"汇率按 6.8 算"）。✓

**纯现金流（Excel 汇总表 G20–W35）**：第 22 行是"之前发出的批次"（手填 4,000 套 × 原表格货值头程 = 38,525 美元，当月预计回款记成负的货值头程）；23 行起每月：当月发货数量（备货计划的美森 / 空运）× 单价 = 当月发货货值头程 Q；当月利润 R（下单月）；当月结算利润 S（回款月）；当月预计回款 T（回款月）；累计 W = ΣT（含 22 行负数）− ΣQ；回款流覆盖 U = 当月 W ≥ 未来三个月 Q 之和；利润覆盖 V = ΣS ≥ 未来三个月 Q 之和。工具：priorShip（起点前发出的批次）让累计从负数起步 ✓；shipCost 按批次表每批自己的单价 ✓；payback / settleProfit / profit ✓；cum、cumSettle ✓；覆盖的比较对象 ✓。原表格 11 天：工具 11 月累计 −25,041 美元、12 月 −34,105；Excel −38,525、−47,589，差的 13,484 美元全部是首批 4,000 vs 2,600 的数据差（速览第 8 条），12 月增量 −9,064 两边一样。

**应改（速览第 1 条）**：Excel 的 U/V 在两种情况下显示"数据不足"：后面不够三个月，或者未来三个月里**任一个月**备货计划没填发货（V/W 列空）。工具只有前一种；批次表未来三个月没发货时 need = 0，累计 ≥ 0 就显示"已覆盖"，< 0 显示"未覆盖"。"已覆盖"在这里没有意思（没有要覆盖的钱），全年表的两行覆盖也会这样显示。建议：未来三个月批次表没发货 → 显示"数据不足"（或"无发货计划"），和 Excel 同口径。

**全年表（目标汇总表）**：1–14 行全是 OFFSET 自月份统计和纯现金流 U/V：单量、销售额、日均、增幅、广告、TACOS、货值、头程、回款（O 列，按回款月）、利润率、利润、两行覆盖；工具 annual() 给的就是这些字段，13 列，"首批备货"按批次表，实际行和偏差是方案稿要的新增 ✓。"项目全年汇总"（L39–R39：销售量、总货值按卖出、总头程按发货含之前批次、总货值头程、发货 / 空运 / 海运数量）对应 project ✓。

**周汇总**：周键和 Excel A 列一样（周日起，YEAR-W + WEEKNUM(周起始日)；跨年的 2027-01-01 两边都落在 2026-W53），四列汇总一致；差别只是 Excel 从首日起连续列周（空周为 0），工具只列有数据的周（建议）。

**提醒用户（速览第 7 条，不是工具的事）**：Excel 纯现金流第 23 行（2026 年 11 月）的 O23 引用备货计划 V（美森）、P23 引用 W（空运），和 24 行起（O = 空运 W、P = 美森 V）正好相反；L23 的公式是 `=$K$21*P23`，用了空运单价，24 行起是 `$L$21`。现在 11 月没有发货所以算出来都是 0，以后在 Excel 里填 11 月发货会算错。另外 O/Q/S/T 列的 SUMIFS 写死了 `$AL$4:$AL$14` 等 11 行范围，日表加行后这几列不会跟着动。工具按意图实现，不受这两处影响。

## 五、有没有替用户下判断（重点 5）

**没有。** 我在 ui.js、page.html 里搜了"推荐 / 排名 / 最优 / 建议 / 可行 / 走得通 / 红绿灯"和所有颜色类：

- "推荐""排名"各出现一次，都在方案对比页的说明"没有排名、没有推荐"里；"建议"一次，是转述财务包"建议的 3 批补货"。
- 方案对比表按运营方案、工具方案的固定顺序并排，没有按任何指标排序（代码里的 sort 只有按日期和批次发货日）；没有"最优""走得通 / 走不通"这类判定。
- 颜色：红色（--warn）只用在日表"断货 · 少卖"格（方案稿要求"到 0 那天标红'断货'"）和删除 / 恢复默认按钮；没有红绿两色的状态灯。
- "15 号发薪够不够""到期货款那天够不够"显示的是"N 次不够，差 ¥x"或"都够"，是方案稿表五里要求的事实数，不是判定。纯现金流的"已覆盖 / 未覆盖"是用户 Excel 自己的列。
- 工具出的三套方案只是按参数生成、算账、并排；没有默认勾选、高亮或排到前面的"工具觉得好"的那套。

唯一接近"容易误读"的是速览第 3 条：方案对比"回款什么时候来"各月是"打款 − 当期广告"的净额，已在表头注明，但高开方案 11 月的 −¥345,671 容易被读成"到账是负的"。这是表述问题，不是判断。
