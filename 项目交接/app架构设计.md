# 推广 × 现金流 平衡工具：架构设计（第一版，2026-11-01）

> 给独立审核线程：请对照《指标与联动说明（定稿）》和《审核意见（第 1–3 轮）》复审本架构和 `项目交接/推广现金流工具/` 里的实现。算法定稿不变，这里只是把它做成可运行的东西。

## 一、要回答的问题和对应输出

| 用户的问题 | 工具给的数（报告第一屏六张卡） | 从哪里算 |
| --- | --- | --- |
| 推广花多少 | 广告合计（美元、人民币）、每套广告、每套广告上限（止损线）、是否超上限 | 推广层每日广告之和；每件账 |
| 花多久 | 推广起止日和天数；断货日和丢单数 | 推广阶段；引擎逐日库存（缺货丢单） |
| 什么时候回款 | 首笔到账日、平台净到账合计、回款高峰月；周表（本周到账、累计、已下单未到账） | 引擎现金事件（释放分布 + 14 天打款） |
| 现金什么时候最紧 | 最低余额和日期、低于底线天数、要垫多少 | 资金层逐日账 |
| 工厂到期付得清吗 | 每笔货款/头程/关税到期日的余额和缺口 | 逐日账在到期日取值 |
| 团队能被供养吗 | 已计入的团队开支、每月可额外拨、期末余额、期末库存 | 逐日账 + 可拨算法 |

另有：按月表（卖出、销售额、广告、平台到账、货款、团队开支、月末余额、月内最低、已下单未到账、欠工厂未付、经营贡献、可额外拨）、每件账与止损线、反推（到期前至少卖多少件）、coupon 档 × 推广节奏 方案对比矩阵、待确认参数清单、引擎提示。

## 二、三层结构

```
输入表（Excel / JSON）
   │
   ▼
① 推广杠杆层  promo_layer.py（我们写）
   推广阶段 → 逐日 单量 / 广告 / 售价 / coupon 使用率 / FBA（淡旺季）
   coupon 连续段 → ≤30 天一个活动（引擎规则），$5 固定 + 2.5% 变动封顶 $2,000
   每件的账：平均成交价 − 佣金 − FBA − 退款 − 退货处理费 − 券费 − 仓储 − 货值头程关税 + 可再售回库 = 扣广告前每件剩
   每件广告上限 = 扣广告前每件剩（团队一分不拿）；TACOS 上限 = 上限 ÷ 平均成交价
   │  months[]（daily 模式）、coupons[]
   ▼
② 产品层  同事 D08-FLEX-1.7 引擎（原样，不改一行）
   期初批次与起点剩余量、FIFO 成本层、逐日销售（缺货 lost）、按价选佣金档、
   退款 = 退货率 × (成交价 − 佣金 + MIN($5, 佣金×20%)) + 退货物流，可再售按成本回库，
   仓储 = 日末库存 × 月费，释放分布 + 14 天打款日历，货款/头程按账期到期日，
   每周一按"覆盖天数 + 安全天数"自动建议海运补货，补货货款头程同样按账期
   │  cash_events[]、daily[]、monthly[]、batches[]、warnings[]
   ▼
③ 资金层  cash_layer.py（我们写）
   + 起点现金、现金底线
   + 团队固定开支（每月几号付）、一次性费用（上新、Vine、拍摄）
   + 关税（每件美元 或 按采购价比例，到仓时付；起点前到的默认已付）
   + 广告出账方式：花费当天 / 下个打款日从余额扣 / 信用卡还款日（刷卡后 ≥N 天的下个还款日）
   + 断货停广告：断货日广告按 卖出÷计划 缩减，再跑一遍引擎
   = 逐日余额 → 最低点、穿底日、工厂到期日余额、月表、周表
   每月可拨 = max(0, 月末之后所有日子的最低余额 − 底线 − 之前已拨)
   反推 = (到期前必付 − 起点现金) ÷ 每件拿回(平台净回款 − 广告 − 仓储)
   方案矩阵 = coupon 档 × 单量倍数（广告随比例）各跑一遍
   │
   ▼
报告.html + 9 个 CSV + 结果摘要.json + 引擎输入.json
```

## 三、和定稿、审核意见的对照

| 定稿/审核要求 | 实现 | 备注 |
| --- | --- | --- |
| 货款按账期到期日付，不按发货当月 | 引擎 shipments 的 purchase_months / freight_days，或 paid/unpaid + 付款日 | 第二批账期待确认 |
| 广告费单独按实际出账日算 | 资金层三种出账方式 | 默认"花费当天"，最保守 |
| 关税最优先确认 | 单独一项，到仓时出账 | 默认 0，报告红色标注 |
| 缺货按丢单，输出断货日、补货下单日和账期 | shortage_mode=lost；引擎自动补货批次表 | 补货周期待确认（30+30 vs 35+28） |
| 价格档 × 推广节奏 对比 | 方案矩阵 | 默认 coupon 0/20/30% × 0.5/1/1.5 倍 |
| 反推每件广告上限、止损线（TACOS 上限） | 每件账表 | 和定稿表的数同方向，退款公式按引擎（更细） |
| 滚动借款条件：每月卖出 × 每件剩 ≥ 团队开支 | 月表"经营贡献"对比团队开支；"欠工厂未付"逐月 | 贡献是权责口径 |
| 回款用释放分布 + 14 天打款，仓储按库存天数，Coupon 费 $5 + 封顶，FIFO | 引擎原生 | 采用同事口径 |
| 起点现金、团队开支与付款日、每月可拨 | 资金层 | 同事引擎没有的都加在这层 |
| 每周用实际数据替换假设 | 改推广阶段的 CPC/转化率/单量重跑 | 第二版做"实际 vs 计划"对照页 |

## 四、默认参数来源与冲突

默认取同事 2026-10-29 保存的 Y背方案（2,600 套、$24.83 不开 coupon、广告 $21,852、采购 55.5 + 头程 5、6 个月账期、30 + 30 天补货）。另给一套"原表格推广假设"（4,000 件、$29.99 + 30% coupon、CPC 7→3.4、转化 12%、每天 200 单）用来和定稿结论对照。两套的差异和所有待确认项列在输入表"待确认"页和报告末尾，共 17 项，关税最优先。

默认跑出来的结论（真数未确认，仅说明工具能回答什么）：
- 同事方案 + 示例团队开支 ¥30,000/月：广告每套 $1.29 在上限 $2.66 内；不断货；3 批补货共约 1.4 万套；最低余额约 −¥16.5 万（2027-07，付完 6 月货款之后）；8 笔到期有 5 笔不够；可额外拨 ¥0。去掉团队开支，尾期现金 ≈ ¥7.6 万，和同事程序的 ¥75,609 对得上（差 ¥14 是口径差异，审核第 4 轮核对：本工具多算了 2027 年 4–6 月的仓储 ¥2,982，同事程序止月更早；同事程序另含期前投入 ¥2,000；两项对齐后差 ¥2）。
- 原表格假设：每套广告 $17 远超上限 $1.62；12/4 断货、丢单约 6,100 件；最低余额约 −¥99 万。和定稿"按现设定每单广告费需 < $0.91 才不亏"同向。

## 五、第一版的边界与第二版计划

第一版是命令行 + Excel 输入表 + HTML 报告，纯 Python 标准库，本机和云端都能跑。没做的：
1. ~~交互界面~~ → **已做（2026-11-01 当天）**：网页版 https://claude.ai/artifact/ThBASVeKg4kgniRuHU2t1d，源码在 `推广现金流工具/app/`（page.html 外壳 + ui.js 界面 + model.js 模型，`python3 build.py` 打包成一个 HTML；`沙盘网页（可直接打开）.html` 可本地双击打开）。Pyodide 因网页沙盒不能加载被放弃，改为把推广层 + D08 引擎 + 资金层逐行移植成 JS（model.js），用 compare.js 对三套输入与 Python 的结果逐项对照（全部一致）。界面按 app 做：总览（走得通 / 走不通、三个杠杆：节奏 / coupon / 关税、六个数、两张图、六个问题）、分 5 步填数（推广阶段是卡片）、方案对比、明细、设置；手机底部导航、电脑左侧栏、深色模式。推荐规则：coupon 档 × 节奏 0.5 / 0.75 / 1 / 1.5 / 2 倍全跑，"可行" = 工厂每笔都够且全程不低于底线，可行里取"期末余额 + 期末库存货值"最大（并列取广告少的），没有可行的取最少垫钱的；另给"要走得通：现金再多多少 / 关税不超过多少 / 团队开支压到多少"（二分搜索）。参数只存在浏览器本地。
2. "实际 vs 计划"周更页：每周填实际 CPC、转化率、单量、到账，和计划对照，触发止损提示。
3. 目标倒算（给定到期日、未付货款、团队开支，搜最省广告的单量/价格组合）：同事引擎有 goals/target_search 模块，可复用。
4. 入库配置费、库龄附加费、预留金、店铺其他产品共用余额。

## 六、请审核重点看

1. 资金层"每月可拨"的定义是否就是用户要的"每月能拿出多少养团队"。
2. 反推公式是粗算（不计回款滞后、不计补货批次销售），是否要改成在引擎里逐日算。
3. 断货停广告的处理（按卖出÷计划缩减）是否合理，还是应该整段停。
4. 方案矩阵只改 coupon 和单量倍数，CPC/转化率不变；缓推时自然单起不来的风险没有建模。
5. 每件账里的仓储按"平均在库天数"估，和引擎逐日仓储不完全一致，用途只是止损线。
